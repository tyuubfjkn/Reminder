## User outcome
DeepSeek can discuss ordinary topics, including learning/life, without turning everything into a task. When a task action is suggested, display its exact proposal; nothing is saved until the user confirms it. Direct commands also require confirmation. Example: "I want cake today at four" -> dated 16:00 preview -> "make it five" -> replacement 17:00 preview -> "yes" -> saved receipt. Planned time is independent of deadline. Time zone follows Windows automatically. The user explicitly dislikes the empty/basic current layout and crude Undo feedback; this task is a product-quality visual/interaction pass, not just adding buttons.

## Backend contract to consume
- Manual v1 and assistant v1 markers stay unchanged. `assistant.getConfig/configure` additionally return `requiresConfirmation: true` on this backend. Keep optional feature detection. Never silently downgrade new confirmation UX to auto-apply.
- `Task.plannedAt` is `{at: UTC ISO string, timeZone: IANA zone} | null`; create/update accept it separately from deadline. Copy the canonical types into the renderer's contract mirror; older test tasks may default missing plannedAt to null at the compatibility boundary.
- New reply outcomes: `chat`, `proposal`, `cancelled`, alongside `clarification`, `unsupported`, `applied`, `undone`. Chat is ordinary conversation, not an error or “No changes made” badge. Applied/undone alone trigger task reload. A proposal must not optimistically insert/update tasks.
- `reply.proposal = {id, expiresAt, changes}`. Each change has kind, title, optional taskId, exact normalized fields, and (for updates) previous values of changed fields. Display actual proposed values, never parse model prose to determine a write. Preserve explicit nulls as “clear this value”.
- On **every** follow-up while a proposal is active, send its currently displayed `proposalId` and `conversationId`. Confirm/Don't add buttons also send `decision: 'confirm' | 'cancel'`. Text is still required; use a short localized label for buttons. Typed standalone yes/no in English/Chinese is recognized by the backend. Other text edits/replaces or switches topic. The model cannot authorize a commit.
- Editing invalidates the old proposal before the network call, including when the edit fails. Keep its buttons disabled. Exact same request/body/ID can retry the edit. A new proposal has a new ID; old cards never become clickable again. Preview replies/choices make zero task writes.
- Preview expiry is 10 minutes; conversation idle expiry is 30 minutes. Proposal mismatch/expiry/stale snapshot returns `CONFLICT` (proposal-specific errors may have `field: 'proposalId'`); conversation loss returns `AI_CONVERSATION_EXPIRED`. Show an explicit expired/stale state and a path to start a fresh proposal/conversation. Do not simply re-enable the old buttons.
- Confirm retries must reuse the identical input/requestId; transient STORAGE_ERROR can retry only that exact confirmation. Successful confirmation's requestId is the Undo target, not the earlier proposal message's ID. Same-ID replay after restart or Undo cannot duplicate effects.
- Preserve all previous PR #7 guards: no stale structured choices during failed/in-flight requests, same-ID retry, composer clearing after padded successful sends and Try again, preserving newer drafts, and history/Undo without a key. No automatic retries. A failed/unknown confirmation must be resolved by its identical retry before offering another potentially duplicate confirmation.
- `settings.get/update` return `timeZoneSource: 'system'` in desktop. Manual timezone update is rejected. Optional `settings.onChanged(callback)` returns unsubscribe; its callback contains no state, so reload settings.get(). Also refresh on focus. Never infer timezone from UI language. Refresh displayed current offset over DST transitions as the clock advances even if the zone ID stays the same.
- On system-zone change, show the new zone and mark pending previews stale; no stale confirmation may write. Coordinate any recovery ambiguity with Codex instead of bypassing proposal ID checks. Preserve typed drafts when settings/tasks refresh.
- Removing the key blocks new model calls, not local history/Undo. Existing validated proposal confirmation/cancellation is local and can remain available without a key until expiry. Do not leak keys in logs/screenshots/fixtures.

## Concrete layout and visual direction
- Use a compact persistent navigation rail/sidebar (Today, Tasks, Assistant, Settings) and a real workspace. Replace the current full-width blank margins around an 820px form with a responsive primary content area. At wide widths show useful task context alongside conversation; at 760px collapse secondary context and keep the main action usable without horizontal scrolling.
- Today: real date, small pending/completed summary, planned today, upcoming deadlines, and unscheduled tasks. Counts/groups derive from real data and current system zone. Distinguish planned time from due date. No fake charts, invented activity, empty calendar grids or notifications/auto-scheduling claims.
- Quick add should be prominent but not a large permanently expanded form dominating the page. Support keyboard access/Ctrl+N, a deliberate details drawer or expandable editor, priority/estimate/plannedAt/deadline, and inline validation. Preserve manual task editing/completion/Undo behavior and optimistic revision protection.
- Assistant: readable messages, comfortable line length, sensible spacing, scroll behavior, persistent composer, meaningful empty-state starters. Make ordinary chat, pending proposal, committed receipt, clarification and error visually distinct. Retain draft across navigation. Prevent sending or resetting the conversation while a request's outcome is unresolved.
- Proposal: structured card with title/action, exact date, local time/offset and zone, estimated duration/priority and changed-field before/after when present. Buttons **Confirm changes**, **Edit**, **Don't add**. Edit focuses the composer with a useful hint; it must not save anything. Show Pending/Confirmed/Cancelled/Expired states. Only the latest active card is actionable; disabled/superseded states remain readable.
- Undo: keep success feedback compact and dismissible without shifting the entire page. The Undo action opens an accessible detail dialog showing affected task names, batch scope and known before/after values; no fabricated old values. Final **Undo changes** / **Keep changes** buttons. Focus trapping, Escape/cancel, return focus, busy/error/conflict states and completion feedback are required. Do not make Undo time out arbitrarily. Assistant history retains accessible Undo entry points.
- Settings: polished sections for language and AI credentials/model, plus a read-only time-zone row with current region/offset and **Follows system**. Remove the timezone dropdown/free text. Key input remains write-only and clears after success.
- Restrained accent, clear headings, surface hierarchy, spacing and icons with accessible names. Light/dark support. English (en-US) first, Simplified Chinese second; original task text never translated. Do not fill space with decorative cards at the expense of readability.
