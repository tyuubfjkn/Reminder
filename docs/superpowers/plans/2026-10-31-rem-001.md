# REM-001 Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task. Steps use checkbox syntax.

**Goal:** Persist manual tasks and locale preferences and provide a narrow desktop contract for CC.
**Architecture:** Local SQLite service, structured dispatcher, Electron context bridge and separately owned React renderer.
**Tech Stack:** Node 24 ESM, node:sqlite, node:test; Electron shell; React/TypeScript renderer owned by CC.
**Spec:** docs/superpowers/specs/2026-10-31-reminder-design.md
**Contract:** packages/contracts/api-v1.d.ts 1.0.0

## Global Constraints
Windows desktop only. First-run en-US; optional zh-CN. No credentials, AI, scheduling or reminders in REM-001. Preserve date-only deadlines. Reject stale updates. Do not claim desktop/installer validation from Node tests.
Baseline: 4b7592e7dd0e9fe49c8e0b0a014830a31682272d. Codex implements backend directly; independent whole-branch review afterward.

## Review Focus
- Invalid dates, offsets, unknown fields and malformed JSON: reject without partial persistence.
- Stale or simultaneous edits: preserve the first committed update.
- Corrupt/unwritable or future-schema databases: fail safely without erasing user data.
- Locale switching and a non-US time zone: preserve task text and date-only semantics.
- Untrusted iframe/window IPC and raw exceptions: no data access or internal detail leaks.
