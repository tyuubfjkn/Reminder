# REM-002 natural-language operations implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Execute Codex work inline, then one fresh independent code review; CC implements the renderer separately.

**Goal:** Turn bilingual user input into validated, persistent, undoable task changes through DeepSeek.
**Architecture:** A bounded provider adapter proposes typed operations; the local coordinator resolves times/ambiguities and commits via SQLite with durable idempotency and undo. BYOK is encrypted by Electron in the main process. The manual bridge remains backward compatible.
**Tech Stack:** Existing Electron45.2.1, Node24 ESM, node:sqlite, React/TypeScript renderer (CC); built-in fetch, no new runtime package.
**Spec:** docs/superpowers/specs/2026-10-31-reminder-design.md v1.1.0, REM-002 section.

## Global constraints
- User selected BYOK; never bundle/read back/log a provider key. Only fixed official HTTPS endpoint.
- Optional assistant v1 in packages/contracts/api-v1.d.ts; manual v1 marker and behavior unchanged.
- One input <=4000 units, <=20 operations, <=200 contextual tasks, <=256KiB response,30s network timeout, no automatic retry.
- Application controls UTC conversions, revisions, atomicity, receipt wording and undo; model output is untrusted.
- No reminders/scheduling/recurrence yet; no live model claim without an actual configured key.

## Review focus
- Model output must not bypass validation, invent task IDs or execute unsupported tools (Tasks2/3).
- Replays after restart or undo must not duplicate effects; same ID/different input must conflict (Task1).
- Manual edits during a model wait, including timezone changes, must fail the whole batch (Tasks1/3).
- DST gaps/folds and duplicate task titles must not cause a silent wrong deadline/target (Task3).
- Corrupt/unavailable secure storage must not disable manual tasks or leak a key; config races must not resurrect removed keys (Task4).
